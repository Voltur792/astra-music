# Поддержка платформ

**Windows — основная платформа. Linux и macOS — экспериментальная поддержка.**

Полная ручная проверка на Linux и macOS ещё не выполнена. Автоматические проверки на Windows, Ubuntu и macOS доступны во вкладке Actions, workflow «Platform checks». Они проверяют зависимости и программную логику, но не заменяют проверку микрофона, звука, окон, системных разрешений и аккаунтов в обычном графическом сеансе.

Astra выпускает хосты плагинов для Windows x64 и Linux x64. macOS и ARM пока зарезервированы без выпускаемого хоста: наличие кода macOS не означает, что плагин уже можно установить в Astra на Mac. См. [официальный список платформ](https://github.com/mihailinl/AstraPlugins/blob/master/astra-plugin-cli/vendor/astra-plugin-manifest/src/platform.rs).

Данные Windows сохраняются в прежних папках. В Linux используются стандартные XDG-папки пользователя, в macOS — `~/Library/Application Support`. Перенос личных ключей и аккаунтов между ОС не выполняется автоматически. `ASTRA_CONFIG_DIR` позволяет указать нестандартную папку конфигурации Astra.

Для собственных настольных окон на Linux нужны зависимости `pywebview[qt]`, а в сеансе Wayland — также Qt Wayland platform plugin. Пользовательские `QT_QPA_PLATFORM` и `PYWEBVIEW_GUI` сохраняются. Работа поверх всех окон и расположение зависят от композитора. Изменения относятся к окнам плагинов; общий оверлей Astra обновляется отдельно разработчиком Astra.

## Музыка

Постоянный плеер и Spotify находят Edge/Chrome/Chromium в Linux и `.app`-пакеты на macOS. Для Spotify нужен браузер с доступным Widevine/DRM (Edge или Google Chrome); наличие Chromium само по себе этого не гарантирует. Требуется Node.js 22+. Аккаунт, подписка, доступность сервиса и треков по региону проверяются в реальном браузере.

В Linux для настольного виджета устанавливаются `pywebview[qt]` и Qt Wayland plugin; в macOS используется Cocoa. Универсальный `requirements.lock` содержит отдельные условия для Qt, Cocoa и Windows .NET. Воспроизведение в фоне использует отдельный браузерный профиль; завершаются только его собственные процессы.

Для системного визуализатора Linux нужен PulseAudio или совместимый PulseAudio-сервер PipeWire. В macOS обычного системного loopback может не быть: потребуется настроенное виртуальное устройство вывода/захвата. Микрофон вместо loopback не выбирается. Визуализатор самого плеера от этого не зависит.
